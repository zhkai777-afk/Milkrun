博格华纳工厂物料计划与物流协同平台

面向计划员 / 供应商 / 物流商 / 仓库的四方协同方案——把"计划 → 承诺 → 预约 → 发货 → 收货 → 检验 → 异常补齐"串成一条可追踪的链路
编制：WorkBuddy日期：2026-07-30适用范围：博格华纳宁波工厂 物流部 当前状态：原型已覆盖 8 个页面，本方案用于统一架构与补齐缺口

0 · 一句话心智模型（先理清思路）

把整件事想成一条带"承诺"和"缺口"两根标尺的传送带：
计划员把工厂需求（物料计划）和供应商回复（SAP ASN = 承诺）铺到同一张表上； 供应商确认能发多少、何时发、直送还是让物流商自提； 无论哪种方式，都要先向仓库预约"哪天 + 上午/下午"的收货位； 物流商只负责自提类物料的取货与配送，并把路线轨迹可视化； 货到仓库后录入实收数量、做检验； 一旦"计划 ≠ 承诺 ≠ 实收"，就产生缺口，系统记录缺口并让供应商在后续发货里补齐。

1 · 设计目标与现状盘点

1.1 要解决的核心问题

  • 数据不通：计划、承诺、预约、发货、收货、检验分散在不同环节，靠人工对账，缺口只能在 Excel 里算。
  • 预约无标准：供应商 / 物流商到货时间不固定，仓库收货能力（上午 / 下午托数）无法被前置利用，造成排队或空等。
  • 异常不可追踪：承诺量 < 计划量、实收量 < 承诺量时，没有闭环去"记缺口 → 催补齐 → 验补齐"。
  • 检验两张皮：供应商自检与工厂到厂检用不同模板、互不可见，质量问题追溯困难。
  • 思路分散：已有 8 个原型页面，但缺少统一架构，新需求一来容易重复造页面。

1.2 设计目标

业务目标

  • 计划与承诺同源可视，缺口实时计算
  • 所有到货（直送 / 自提）必须"先预约后到厂"，且预约时段受仓库上午 / 下午能力约束
  • 异常 100% 留痕，缺口可追踪到"谁、差多少、何时补齐"
  • 检验模板统一，自检与到厂检在同一上下文

体验目标

  • 四个角色各有一个"工作台"，只看到自己该看/该做的
  • 物流路线可视化，直送 vs 自提一目了然
  • 移动端（仓库 / 物流部现场）与桌面端（计划员 / 供应商办公）双形态
  • 原型阶段用 localStorage，可平滑切到后端 + SAP 集成

4 · 核心概念与数据模型

所有页面共享同一套实体。最关键的是把"承诺"和"缺口"定义清楚，这是你异常场景的底座。

4.1 实体与关键字段

实体关键字段说明
物料计划行
计划员		物料编号、SAP供应商编号、供应商名称、计划员、采购凭证、计划发货日期、计划到货日期、计划发货数量、配送方式(直送/自提)、指定物流商、标准装箱/装托数量、箱数、托数、库区工厂需求侧。每行 = 一个"物料+采购凭证"

4.2 两根标尺（务必区分）

① 承诺缺口 = 计划 − 承诺

供应商回复的承诺 < 工厂计划时产生。由计划员管控：可调整承诺（留原因历史），或保留缺口等供应商后续 ASN 追加。

示例：计划 500,000，ASN 承诺 480,000 → 承诺缺口 20,000。

② 到货缺口 = 计划 − 实际到货

实际收到 < 计划（或 < 承诺）时产生。由仓库收货触发，进入补齐队列，供应商后续发货时递减余额。

示例：计划 500,000，实收 470,000 → 到货缺口 30,000（其中 20,000 是承诺缺口延续 + 10,000 是发货不足）。

补齐逻辑：每行维护 累计承诺 与 累计到货。未补齐余额 = 计划 − 累计到货（或按期初口径 − 累计承诺）。供应商针对同一"物料+采购凭证"在后续 ASN/发货中追加，系统按 key 自动关联并递减余额，直到归零转"已补齐"。

7 · 异常场景与缺口补齐闭环（重点）

这是你描述里最关键的"计划与现实不一致"的处理。目标是：任何不一致都留痕、可追踪、能补齐。

7.1 状态机（物料计划行）

计划中→ 待供应商确认→ 已承诺→ 已预约→ 已发货→ 已到货→ 检验中→ 检验合格
承诺缺口↺ 补齐中→ 已补齐 | 到货缺口→ 检验不合格→ 退换/特采

7.2 异常场景处理矩阵

异常触发点系统动作责任方
承诺量 < 计划量
（产能/缺料）		ASN 导入 / 供应商确认记录承诺缺口；计划员可调整承诺（留原因）或保留缺口进补齐队列计划员供应商
实收量 < 承诺量
（发货不足）		仓库收货记录到货缺口；余额进补齐队列；提示计划员催补仓库计划员
实收量 > 承诺量
（超发）		仓库收货提示超发；可收货或拒收；超收部分计入下一期或退供应商仓库
未预约到货到厂无预约拦截提示"无预约"；引导先补预约或走异常放行（需运营审批）运营
检验不合格到厂检标记不合格→退换货/特采；影响补齐与供应商绩效仓库
逾期未到超过预约日期预警；转异常看板；催发货计划员

7.3 缺口补齐闭环（核心算法）

① 入账
缺口产生
承诺/到货缺口写入补齐队列，状态=补齐中
→
② 关联
同源归集
按"物料+采购凭证"key 聚合多条缺口
→
③ 催补
通知供应商
供应商工作台显示"待补齐缺口"
→
④ 补齐
后续 ASN/发货
同 key 追加承诺/到货，余额递减
→
⑤ 闭环
余额=0
状态转"已补齐"，看板消除
设计要点：补齐不删改原记录，而是追加。这样既保留"当初承诺了多少"的审计链，又能追踪"后来补了多少"。余额公式：未补齐余额 = 计划量 − Σ(各次实际到货量)（或按期初口径用承诺量）。

8 · 预约与物流路线设计

8.1 预约规则（上午 / 下午）

  • 谁发货谁预约：直送由供应商预约；自提由物流商预约。
  • 必须预约后到厂：仓库收货以预约时段为准，无预约拦截或走异常放行。
  • 时段受能力约束：预约的"上午/下午"直接校验 index.html 的库区每日托数——该时段已满则不可约，提示换时段。
  • 预约信息：日期 + 上午/下午 + 关联计划行/采购凭证 + 物流路线。

直送 路线

供应商仓→ 干线直达 →工厂库区

承运方=供应商自营/其签约车；供应商本人预约上午/下午。

自提 路线

供应商仓→ 物流商取货 →干线→ 到厂工厂库区

多一个"取货"节点；物流商预约上午/下午，并负责轨迹可视化。

8.2 物流路线可视化

沿用 appointment-calendar.html 的路线弹窗思路，标准化为：起点 →（取货）→ 干线 → 中转 → 到厂，配里程/时长/进度条。直送与自提用不同颜色与图标区分（已在原型中用橙色=送货、绿色=自提）。建议补：路线节点由"物料配送方式 + 指定物流商"自动生成，而非手工填。

9 · 检验设计（新模块）

你明确要求：供应商按工厂模板填自检，工厂到货后填检验。这是当前最明显的缺口，独立成模块。

9.1 三层结构

① 模板
工厂检验模板
检验项目(外观/尺寸/性能)、标准值、允差、判定规则
→
② 自检
供应商自检
发货前按模板填实测值 → 合格/不合格
→
③ 到厂检
工厂到厂检
到货后同模板填实测值 → 合格/特采/不合格

9.2 检验模板字段（示例）

检验项目标准值允差实测（供应商/工厂各填）判定
外观无划痕/无毛刺——合格/不合格
关键尺寸 A50.00 mm±0.05—合格/特采/不合格
性能（扭矩）≥ 25 N·m——合格/不合格

供应商自检

  • 入口：供应商工作台"自检填报"
  • 必须发货前完成，否则限制发货登记
  • 自检不合格需备注原因

工厂到厂检

  • 入口：仓库收货页关联检验
  • 到货后填写，与自检同模板同上下文
  • 不合格→退换/特采，并计入缺口与供应商绩效

两套检验用同一模板版本，便于对比"供应商自检 vs 工厂到厂检"差异，质量问题可追溯到具体项目与批次。

11 · 集成与数据

  • 原型期：沿用各页 localStorage（plans / asn / zones / materials 等 key），保证演示可跑、可迭代。
  • 集成期：物料计划、SAP ASN、承诺、预约、收货、检验统一收敛到后端 API；SAP 作为主数据（供应商、物料、采购凭证）与 ASN 来源。
  • 唯一 key：所有聚合（承诺缺口、到货缺口、补齐）都以 物料编号 + 采购凭证 为关联键，与现有 makeKey 逻辑一致。
  • 权限：四角色按 RACI 收敛工作台；供应商/物流商仅看自己数据（按 supplierCode / carrier 过滤）。

建议顺序理由：你描述里"异常场景"和"检验"是业务最痛、当前完全空白的两块，优先 M1 把"收货→缺口→补齐"闭环跑通，再补自检与预约能力联动，最后才做集成。这样每一期都能独立演示、独立交付价值。
